Business flaws

HIGH · SUPPORTED EVIDENCE

1. Failed article jobs stay active after the error is reported

When a background article job ends with an error, the progress endpoint forwards the error update but does not close the job or clear its active state.

Trigger

When a started article-generation job hits an exception and emits an error progress update, the client continues using the progress stream for that job.

What the code does

The progress stream cleans up only when step == 'complete'. Error updates are streamed to the client, but the job remains in active tracking and the stream continues with heartbeat events.

Business rule

A terminal background job outcome must end progress tracking and clear the active job record for both success and error results.

Basis: WORKFLOW INFERRED

Business downside

Failed article requests stay stuck in progress tracking and stale job records remain allocated.

Impact

Immediate outcome
A failed job remains active after the error is already shown to the user.
Affected party or asset
Browser users monitoring job status and the service's in-memory job tracking state
Scale mechanism
Every error-terminal job follows the same path because cleanup is wired only to the complete step.
Detection difficulty
Users see an error event first, so the continuing open stream and retained job state are easy to miss unless the terminal behavior is checked.
Reversibility
The connected code does not self-clear error-terminal jobs.

How the code reaches the outcome

  • POST /start-job registers a queue in active_jobs and schedules the background workflow.
  • The background workflow sends an error progress message when an exception occurs.
  • GET /progress/{job_id} streams each queued progress message to the client.
  • The progress stream deletes active job state only when the message step is 'complete'.
  • After an error message, the stream stays open and timeout handling continues to emit heartbeat events.

What to change

Ensure every terminal job outcome closes client progress tracking and clears active job state.

Acceptance check

Given A started article job that throws an exception after it has been registered in active job tracking
When The client consumes the progress stream for that job after the error update is emitted and waits for terminal behavior to occur without a success completion event.
Then The stream should terminate and the job should be removed from active tracking on the error path as well as the success path.
